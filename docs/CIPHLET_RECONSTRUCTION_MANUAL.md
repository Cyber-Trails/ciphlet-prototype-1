# CIPHLET — Reconstruction Manual

## Purpose
Permanent recovery document for rebuilding Ciphlet if the installation, storage, computer, or development environment is lost.

This manual must describe the **actual implemented system**. Planned capabilities must be clearly marked as planned/not implemented.

## Repository
Record the dedicated Ciphlet GitHub repository URL, default branch, release/tag information when used, current verified commit, and verification date from actual repository evidence.

## Hardware
Record Pi model/RAM, storage, cooling/enclosure, power, microphone, speaker/audio adapter, display, keyboard/mouse, and optional peripherals.

## Operating system
Record OS/distribution, architecture, version, kernel, hostname, user, and relevant network configuration.

## Software dependencies
For each dependency record name, version, installation method, purpose, and configuration location.

## Installation
Document the exact verified sequence for preparing the Pi, storage, OS, packages, runtime dependencies, Ciphlet configuration, voice, memory, UI/embodiment, cybersecurity tools, local lab components, startup, and verification.

Do not document guessed commands as verified instructions.

## Voice
Record actual STT, TTS, wake-word, microphone, speaker, audio routing, voice-isolation, and barge-in implementations once verified.

## Memory
Record database/storage, schema/migrations, semantic-memory implementation, retention, no-memory behavior, user memory management, and backup/recovery.

## Learning/training
Record training engine, lesson structure, flashcard/quiz generation, roadmaps, Lab Coach, user-material ingestion, and visual artifact generation.

## Cybersecurity tools
Record only tools actually installed and verified, including version, purpose, execution environment, configuration, verification method, and safe training use.

## Lab environments
Record local containers, local ARM VMs, external VMs, online platforms, network isolation, and reset/snapshot procedures.

## Workspace/UI
Record UI framework, startup, screen modes, terminal/log/evidence views, dashboard/chart/diagram generation, and embodiment integration.

## Embodiment
Record approved reference assets, sprite/animation assets, atlas generation, runtime state mapping, state-light implementation, and display integration.

Approved visual references remain authoritative.

## Screen/computer control
Record screen-view implementation, screen-control implementation, authorization mechanism, browser automation, desktop interaction, and supported applications.

## Vision
If not implemented, explicitly state that.

If implemented later, record camera, driver, capture method, permission model, processing pipeline, retention, and privacy controls.

## Troubleshooting
For each known failure record symptom, component, diagnostic procedure, verified fix, and recovery procedure.

## Backup
Maintain backups of source, configuration, memory/database where appropriate, approved visual assets, documentation, and this manual.

Never put secrets, API keys, passwords, recovery keys, or credentials into GitHub.

## Recovery principle
A future builder should be able to obtain the repository and this manual and reconstruct Ciphlet without relying on old chat conversations.

Update this manual after significant implemented capability, dependency, hardware, or recovery changes.
