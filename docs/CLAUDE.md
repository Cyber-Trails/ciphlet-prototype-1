# CIPHLET — Claude / Claude Code Project Instructions

## Identity
Ciphlet is independent from CIPHER.

**CIPHLET — Cybersecurity Intelligent Personal Helper for Learning, Exploration & Training**

Pronunciation: **SIGH-flit**

Ciphlet is a learning-first AI companion on Raspberry Pi 5.

Primary roles:
- facilitator
- teacher
- mentor
- learning buddy
- cybersecurity training companion

## Owner priorities
Optimize for:
- time-to-working Ciphlet
- practical capability
- reuse-first implementation
- modularity
- truthful status
- simple hardware bring-up
- future expandability

Do not overengineer Version One.

## Target capabilities
Natural hands-free voice; typed chat in the same session; transcription; spoken responses; "Hey Ciphlet"; selective attention; voice isolation; context-preserving barge-in; semantic learning memory; user-controlled deletion; personalized cybersecurity training; red/blue/purple-team learning; SOC preparation; authorized cyber-tool execution; browser/screen assistance; separate screen view/control; Lab Coach Mode; flashcards/quizzes/roadmaps; image generation; charts/graphs/diagrams/dashboards; terminal/log/evidence workspace; adaptive embodiment; optional future vision; modular hardware.

## Lab philosophy
Use the simplest environment that can accomplish the objective:
1. local Pi tools
2. lightweight containers/isolation
3. limited ARM Linux VM
4. external machine/VM
5. online/browser lab

Do not make VMware Workstation or VirtualBox on the Pi a core requirement.

If a workload exceeds Pi capabilities, explain the limitation and continue via an appropriate external/online environment.

## Voice
Hands-free is primary; push-to-talk is fallback.

Wake phrase: "Hey Ciphlet."

Speech detection is not intent detection.

Barge-in must preserve context.

## Memory
Retain meaningful learning/project history by default.

Completed projects remain retrievable unless deleted.

Explicit no-memory conversations are not promoted to long-term memory.

## Embodiment
Approved reference image and sprite/action sheet are visual authority.

Do not redesign the character.

Sapphire body remains stable; state colors are internal neural/Soma signals.

Yield display space to functional content.

## Security
Cybersecurity activity remains within authorized environments.

Do not weaken or silently import CIPHER governance/security architecture.

## Status discipline
Never report target capability as implemented without actual repository, test, or hardware evidence.

## Repository and reconstruction
Create and maintain a dedicated GitHub repository for Ciphlet, separate from CIPHER.

Maintain a Reconstruction Manual describing the actual implemented hardware/software, dependencies, installation, configuration, voice, memory, training system, cybersecurity tools, workspace/UI, embodiment, integrations, troubleshooting, recovery, and rebuild procedure.

Clearly separate implemented from future material.

Never place secrets in GitHub.

## Engineering principle
Build the smallest useful vertical slice first, verify on the actual Pi, then expand capability by capability.

Prefer mature maintained components and proven patterns over unnecessary reinvention.
